# Full-Stack Interview Project (Movies)

This repository contains a minimal full-stack baseline for a coding interview. The goal is to provide a running app with a simple Movies list, leaving most implementation work to the candidate.

> This project is a simple, functional monorepo (API and frontend), generated by an LLM, intended to evaluate full‑stack engineering skills. It displays a list of movies. The core task is to assess the current implementation and propose improvements to make it better. We emphasize the importance of unit testing, clean code organization, single responsibility, and professional coding practices. Some tasks must be implemented; others may be described and discussed during the interview.

- Stack: Node 20 LTS, Next.js 15 (App Router), Tailwind CSS, TypeScript
- Backend: Express + Prisma + SQLite (PostgreSQL integration is a candidate task)
- Package manager: npm workspaces

## Quick start

1. Prerequisites: Node 20.x, npm 10+
2. Install dependencies:
   ```bash
   npm install
   ```
3. Seed the database:
   ```bash
   npm run db:seed
   ```
4. Start development servers (API and Web):
   ```bash
   npm run dev
   ```
5. Open the Web app: `http://localhost:3000`

## Architecture

Monorepo layout:

```
full-stack-interview/
  apps/
    api/        # Express + Prisma + SQLite
    web/        # Next.js 15 app (App Router)
  packages/
    types/      # Shared TypeScript types and zod schemas
```

- Communication: REST over HTTP (JSON)
- Validation: zod (shared types/schemas)

## Minimal API (implemented)

- `GET /api/health` → `{ status: "ok" }`
- `GET /api/movies` query params: `q` (search in title), `page`, `pageSize`
- `GET /api/genres` → list of distinct genres

## Frontend (implemented)

- `/` page lists movies (title, year, genre, rating). Minimal styling only.

## Candidate tasks

Focus on correctness, readability, type-safety, accessibility, observability, and developer experience.

### API tasks (apps/api)

- Code organization and app structure
  - [ ] Refactor single-file `src/index.ts` into a clear structure: `src/app/createApp.ts`, `src/server.ts`, `src/routes/*`, `src/controllers/*`, `src/services/*`, `src/middleware/*`, `src/config/*`.
  - [ ] Centralize Prisma in `src/db/client.ts` and inject/depend via module boundaries (avoid importing Prisma directly in route files).
- Initialization and configuration
  - [ ] Validate environment with zod (e.g., `src/config/env.ts`), fail fast on invalid config, keep `.env.example` in sync.
  - [ ] Add request logging (pino) and request ID correlation.
- Health and metrics
  - [ ] Implement `/api/health/live` and `/api/health/ready` (readiness should check DB connectivity).
  - [ ] Expose `/metrics` using Prometheus (`prom-client`): request count, latency histogram, error counts.
- Error handling and validation
  - [ ] Use zod for request validation and add a global error handler that returns a consistent error shape.
- API features and data access
  - [ ] Extend `GET /api/movies` with filters: `minRating`, `year`, `genre`.
  - [ ] Add sorting: `sortBy` (title|year|rating), `order` (asc|desc).
  - [ ] Include pagination metadata: `total`, `totalPages`.
  - [ ] Add `GET /api/movies/:id`, `POST /api/movies`, `PUT /api/movies/:id`, `DELETE /api/movies/:id` with validated payloads.
- Graceful shutdown and lifecycle
  - [ ] Handle SIGINT/SIGTERM, stop accepting new connections, close HTTP server, and disconnect Prisma with a timeout fallback.
- PostgreSQL integration
  - [ ] Switch Prisma provider to `postgresql` (via env) and create/migrate schema; verify CRUD, filters, pagination.
  - [ ] Keep SQLite as a local fallback via env switching.
- Testing and docs
  - [ ] Add Vitest + supertest for unit/integration tests: validation failures, success paths, pagination/sorting, health/readiness.
  - [ ] Optional: Provide OpenAPI (Swagger/Redoc) docs for endpoints.

### Web tasks (apps/web)

- Component and folder organization
  - [ ] Organize components under `components/ui`, `components/movies`, `components/common`.
  - [ ] Create focused, reusable components: `MovieCard`, `MovieGrid`, `RatingBadge`, `FilterBar`, `SortSelect`, `Pagination`, `SearchInput`, `EmptyState`, `ErrorState`, `LoadingSkeleton`.
- API layer and data fetching
  - [ ] Implement `lib/api.ts` with typed fetch helpers for list/detail and mutations.
  - [ ] Use server components for static/SSR data; use client components and SWR/React Query or custom hooks for interactivity.
  - [ ] Surface errors to the UI with a consistent shape and toasts/alerts.
- Features and UX
  - [ ] Home `/`: URL-driven state for search, filters, sort, pagination.
  - [ ] Detail `/movies/[id]`.
  - [ ] Admin `/admin/movies`: forms with `react-hook-form` + zod, optimistic updates, error handling.
  - [ ] Accessibility: semantic labels, keyboard navigation, and focus management.
  - [ ] Performance: memoize heavy UI; consider simple list virtualization if needed.
- Component tests
  - [ ] Add Vitest + React Testing Library. Test `MovieCard`, `FilterBar`, `Pagination`, and homepage list behavior (search/sort/paginate).

### Tooling and production readiness (root and apps)

- Linting/formatting
  - [ ] Set up ESLint (TypeScript, React, Next, Tailwind) and Prettier at the root; add `lint`, `lint:fix`, `format` scripts; fix violations.
- Security and robustness (API)
  - [ ] Add security headers (helmet), proper CORS policy, and basic rate limiting.
  - [ ] Validate all env vars and avoid insecure defaults.
- Observability
  - [ ] Structured logging (pino) with request IDs; wire metrics to `/metrics`.
  - [ ] Optional: outline minimal OpenTelemetry tracing setup.
- CI and quality gates
  - [ ] GitHub Actions to install, build, typecheck, lint, and test across workspaces; add coverage thresholds.
- Release/deploy
  - [ ] Production builds for web and API; optionally add Dockerfiles and `docker-compose.yml`.
- Documentation
  - [ ] Update this README with architecture, scripts, run/test steps, and design decisions.

### Submission guidelines

- Provide a summary of architectural changes and reasoning.
- Include instructions to run tests and a brief test results summary.
- Note any trade-offs and follow-ups you would prioritize next.
